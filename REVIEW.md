# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `list_employees` L93 | `skip = page * page_size` — off-by-one. Page 1 skips 20 records instead of 0. | `GET /employees?page=1` returns empty items on a non-empty collection. | Changed to `(page - 1) * page_size`. |
| 2 | `list_employees` L94 | `count_documents({})` always counts the full collection, ignoring the `department` filter. `total` is wrong when filtering. | `GET /employees?department=Sales` returns `total=6` even when only 2 employees match. | Changed to `count_documents(q)`. |
| 3 | `list_employees` L95 | No `.sort()` call. Order is arbitrary (MongoDB insertion order). | `GET /employees` returns employees in a random order instead of `emp_code` ascending. | Added `.sort("emp_code", ASCENDING)`. |
| 4 | `punch_in` L102 | `datetime.fromtimestamp(ms/1000)` produces a **naive local-timezone** datetime, not IST. On any host not set to IST the attendance date and late_minutes will be wrong. | Punch-in at an epoch ms that is 09:28 IST returns a record dated the wrong day on a UTC host. | Replaced with `from_epoch_ms()` which converts to IST-aware datetime truncated to whole seconds. |
| 5 | `punch_in` L102 | `datetime.now()` when `punched_at` is omitted also produces a naive local datetime. | Auto-timed punch-in on a UTC host gets the wrong date and late computation. | Replaced with `datetime.now(timezone.utc).replace(microsecond=0).astimezone(IST)`. |
| 6 | `punch_in` L101 + L113 | No 404 guard after `db.employees.find_one()`. If the employee does not exist, `emp` is `None` and `emp["shift_start"]` raises `TypeError` → 500. | POST `/attendance/punch-in` with an unknown `emp_code` returns 500 instead of 404. | Added `if not emp: raise HTTPException(404, ...)` immediately after the lookup. |
| 7 | `create_employee` L79–80 and `punch_in` L104–105 | Check-then-insert is not atomic. Two concurrent requests with the same key can both pass the check and both insert, yielding two 201s instead of one 201 and one 409. | Load-test with two simultaneous identical POSTs — both may succeed. | Created unique indexes I1 (`employees.emp_code`) and I2 (`attendance_logs.{emp_code,date}`) at startup; wrapped `insert_one` in `try/except DuplicateKeyError → 409`. |
| 8 | `create_employee` L82 + L85 | `created_at = datetime.now()` — naive datetime stored and returned. FastAPI serialises it as an ISO string (e.g. `"2026-10-12T12:00:00"`), not as an epoch-millisecond integer. | Response body has `"created_at": "2026-10-12T12:00:00"` instead of `1728734400000`. | Replaced with `datetime.now(timezone.utc).replace(microsecond=0)`; added `_serialize_employee()` to convert to epoch ms at the API boundary. |
| 9 | `compute_late_minutes` L37 | Gate is `minutes > 10` where `minutes = int(elapsed_s / 60)`. For elapsed seconds in the range (600, 660), `minutes` floors to 10 and `10 > 10` is `False`, so the function returns 0 instead of 10. openapi example: 09:40:01 → expected 10, got 0. | POST punch-in at 09:40:01 with a 09:30 shift: `late_minutes` is 0 in the response instead of 10. | Changed gate to `elapsed_s > 600`; returns `int(elapsed_s / 60)` when late. |
| 10 | `compute_late_minutes` L35 | `punch_in.replace(hour=h, minute=m, ...)` builds shift-start on `punch_in.date()`. For overnight-shift employees whose IST punch time is in the early morning (< shift_end), `punch_in.date()` is the wrong calendar day, so elapsed time is computed against the wrong anchor. | Punch-in at 01:00 IST for a 22:00–06:00 shift computes lateness against 22:00 on 01-01-2026-07-07 instead of 2026-07-06. | Passed `att_date` as a parameter; shift start is built from `datetime.fromisoformat(att_date).replace(hour=h, ...)`. |
| 11 | `compute_overtime` L46 | `datetime.fromisoformat(date_str).replace(tzinfo=IST)` creates an IST-aware end time, but `punch_out` from the DB is a naive UTC datetime. Subtracting raises `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Any call to punch-out (Phase 02) would crash with a 500. | Redesigned `compute_overtime` to accept IST-aware datetimes for both arguments; built shift-end from `att_date` in IST. |
| 12 | `compute_work_hours` L41 | `round()` uses Python's IEEE 754 banker's rounding (round-half-to-even). R4 requires half-up. Example: `round(8.445, 2) = 8.44`, contract requires `8.45`. | Work-hours at a midpoint value (e.g. 9h 26m 42s) would be rounded the wrong way. | Added `half_up()` using `decimal.Decimal` with `ROUND_HALF_UP`; used it in `compute_work_hours`. |
| 13 | `list_attendance` L144 | `list(db.attendance_logs.find(q))` loads the entire filtered result set into Python memory. Fails on ~100k records as required by the contract. | Large collection: high memory use; slow response; eventually crashes. | Replaced with DB-side `.sort().skip().limit()` using index I3. |
| 14 | `list_attendance` L145 | Python `docs.sort(key=lambda d: d["date"], reverse=True)` — sorts by date only, missing the secondary key `emp_code` ascending. | Two records with the same date may appear in any order. | Replaced with `.sort([("date", DESCENDING), ("emp_code", ASCENDING)])` in MongoDB. |
| 15 | `list_attendance` (no validation) | No check for `date_from > date_to`. Contract mandates 422. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty results instead of 422. | Added explicit check before building the query; raises `HTTPException(422, ...)`. |
| 16 | `punch_in` L119 | `doc["id"] = str(res.inserted_id)` adds an `id` field to the response. The `AttendanceRecord` schema has no `id` field; records are addressed by `(emp_code, date)`. | Response body contains an unexpected `id` key; grader schema check fails. | Removed the `id` assignment entirely. |
| 17 | `punch_in` L110 | `doc["punch_in"] = ts` stores and returns a datetime object. FastAPI serialises it as an ISO string; contract requires epoch milliseconds. | Response `punch_in` is `"2026-07-06T09:28:00"` instead of `1783310280000`. | Added `_serialize_attendance()` which calls `to_epoch_ms()` for all datetime fields. |
| 18 | `create_employee` (no validation) | `EmployeeIn` model did not validate `shift_start == shift_end`. Contract says they must differ. | `POST /employees` with `"shift_start":"09:30","shift_end":"09:30"` returns 201. | Added `@model_validator(mode="after")` in `EmployeeCreate` that raises `ValueError` → 422 when equal. |
| 19 | `EmployeeIn` model | No `emp_code` pattern validation. Contract requires `'^EMP\d{4,6}$'`. | `POST /employees` with `emp_code="ABC"` returns 201 instead of 422. | Added `Field(pattern=r"^EMP\d{4,6}$")` in `EmployeeCreate`. |
| 20 | `GET /health` | No MongoDB ping. Contract says return 503 when MongoDB is unreachable. Always returns 200. | Stopping MongoDB and calling `/health` returns 200 instead of 503. | Added `client.admin.command("ping")` in a try/except; raises `HTTPException(503)` on failure. |
| 21 | `list_employees` and `list_attendance` | `page` and `page_size` query parameters had no bound checking. R10: `page >= 1`, `page_size` max 100. | `GET /employees?page=0&page_size=500` accepted silently. | Added `Query(ge=1)` and `Query(ge=1, le=100)` constraints. |
| 22 | `punch_in` L102 | `punched_at` was `Optional[int]` with no range validation. Contract rejects values below 100,000,000,000 (look like seconds) with 422. | `POST /attendance/punch-in` with `"punched_at": 1000` (seconds-range) returns 201 instead of 422. | Changed to `Optional[EpochMillisField]` with `Field(ge=100_000_000_000, le=4_102_444_800_000)`. |
| 23 | `PunchInIn` L66 | `status: str = "PRESENT"` with no enum restriction. ABSENT and LEAVE are contractually invalid at punch-in. | `POST /attendance/punch-in` with `"status":"ABSENT"` returns 201, writing an invalid record. | Changed to `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 24 | `punch_in` L102 | No second truncation. R1 says instants are truncated to whole seconds before any calculation. | Sub-second punch-in timestamps would affect `late_minutes` calculation. | `from_epoch_ms` calls `.replace(microsecond=0)` on the converted datetime; `datetime.now()` path also calls `.replace(microsecond=0)`. |

## Items inspected and decided NOT to be defects

| Item | Reasoning |
|------|-----------|
| `IST = timezone(timedelta(hours=5, minutes=30))` at L25 | Correct UTC+05:30 offset. Not a defect. |
| `list_attendance` pagination formula `(page-1)*page_size` at L147 | The formula itself is correct (unlike `list_employees`). The defect was the in-memory load (D13), not the formula. |
| `compute_late_minutes` formula `int(elapsed_s / 60)` | `int()` correctly floors the result as required by R2. The defect was only the gate condition (D9), not this line. |
| Default `shift_start="09:30"` and `shift_end="18:30"` in the original `EmployeeIn` | These match the openapi defaults. Not a defect; preserved. |
